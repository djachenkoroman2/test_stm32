# Протокол I2C модуля motor_i2c_module

Версия протокола: **1** (регистр `PROTOCOL_VERSION`). Источник истины в
коде — [`register_map.h`](../../src/motor_i2c_module/register_map.h) и
[`registers.cpp`](../../src/motor_i2c_module/registers.cpp).

## 1. Шина

| Параметр | Значение |
|---|---|
| Роль модуля | slave |
| Адрес | **0x20** (7 бит), `I2C_ADDRESS` в `config.h` |
| Скорость | 100 кГц и 400 кГц |
| Пины | PB10 — SCL, PB11 — SDA (I2C2) |
| Растяжка SCL | используется: модуль может кратковременно удерживать SCL |
| Наибольшая транзакция | 32 байта (буфер ядра stm32duino) |

## 2. Модель: карта регистров

Модуль — это массив регистров по адресам `0x00..0x9F`:

| Адреса | Блок |
|---|---|
| `0x00..0x1F` | общие регистры |
| `0x20..0x3F` | мотор 1 |
| `0x40..0x5F` | мотор 2 |
| `0x60..0x7F` | мотор 3 |
| `0x80..0x9F` | мотор 4 |

Адрес регистра мотора: `0x20 + 0x20 × n + смещение`, где `n` = 0..3 —
номер мотора минус один.

**Порядок байт — little-endian** (младший байт по меньшему адресу).
Типы: `u8`, `u16`, `i16`, `u32`, `i32`. Отрицательные числа —
дополнительный код.

## 3. Транзакции

### 3.1. Чтение

```text
S  [0x20 W] A  [регистр] A  Sr [0x20 R] A  [данные0] A  [данные1] A ... [данныеN] NA  P
```

1. Master записывает **один байт** — адрес регистра. CRC здесь не нужен.
2. Повторный старт (или стоп и новый старт) и чтение 1..32 байтов.

- Байты идут подряд с указанного адреса: так можно прочитать несколько
  регистров или целый блок за одну транзакцию.
- Читать можно с любого адреса, в том числе с середины регистра или из
  резерва (резерв читается как 0). Адреса за `0x9F` читаются как 0.
- Больше 32 байтов за транзакцию не читайте: модуль отдаёт ровно 32.
- Указатель между транзакциями **не сдвигается**: повторное чтение без
  новой записи адреса прочитает те же регистры.
- Данные берутся из снимка, который модуль обновляет на каждом шаге
  контура (каждые 10 мс) и после каждой принятой записи. Многобайтные
  регистры всегда согласованы: за одну транзакцию снимок не меняется.

### 3.2. Запись

```text
S  [0x20 W] A  [регистр] A  [данные0] A ... [данныеN] A  [CRC-8] A  P
```

- Данные покрывают один регистр или несколько **соседних** регистров,
  каждый **целиком** и начиная с его первого байта.
- Последний байт — **CRC-8** (раздел 4). Без правильного CRC запись
  отклоняется.
- Запись применяется **целиком или никак**: сначала проверяются все
  затронутые регистры, затем они применяются по возрастанию адреса.
- Наибольшая запись — 1 байт адреса + 30 байтов данных + CRC.
- Модуль подтверждает (ACK) все байты, даже если запись потом будет
  отклонена: проверка выполняется после стопа. Результат — в регистрах
  `STATUS`, `LAST_ERROR`, `FRAMES_OK`, `FRAMES_REJECTED`.

Записанный адрес регистра становится и указателем чтения, поэтому после
записи можно сразу прочитать тот же регистр без отдельной записи адреса.

### 3.3. Когда записи вступают в силу

| Что | Задержка |
|---|---|
| Разбор записи | следующий проход `loop()`, обычно < 1 мс |
| `MODE` = `COAST` / `BRAKE`, `COMMAND` = `ESTOP` / `COAST_ALL` | сразу при разборе |
| Уставки, `MODE` = `PWM` / `SPEED`, коэффициенты | следующий шаг контура, ≤ 10 мс |
| Видимость в регистрах для чтения | сразу после разбора |

## 4. CRC-8

CRC-8 по алгоритму SMBus PEC (CRC-8/SMBUS):

| Параметр | Значение |
|---|---|
| Полином | `0x07` (x⁸ + x² + x + 1) |
| Начальное значение | `0x00` |
| Отражение, финальный XOR | нет |
| Контрольное значение | `"123456789"` → `0xF4` |

CRC считается по байтам **в порядке передачи, начиная с байта адреса**:

```text
CRC = crc8( [0x20 << 1 = 0x40], [регистр], [данные0..данныеN] )
```

Реализация на C:

```c
uint8_t crc8(uint8_t crc, const uint8_t *data, size_t length)
{
  for (size_t i = 0; i < length; i++)
  {
    crc ^= data[i];
    for (uint8_t bit = 0; bit < 8; bit++)
    {
      crc = (crc & 0x80) ? (uint8_t)((crc << 1) ^ 0x07) : (uint8_t)(crc << 1);
    }
  }
  return crc;
}
```

**Почему CRC только на запись.** Повреждённая запись опасна: искажённая
уставка или режим сразу дойдут до моторов. Повреждённое чтение такого
вреда не наносит, его можно повторить. К тому же slave не знает, сколько
байтов прочитает master, и не может поставить CRC в конец ответа. Если
нужна гарантия при чтении, прочитайте регистр дважды и сравните.

Схема совместима с SMBus PEC при записи: на Linux `i2cset` с суффиксом
`p` (например, `bp`, `wp`) считает тот же CRC. Отключить проверку можно
константой `I2C_WRITE_CRC_REQUIRED = false` в `config.h` — тогда запись
`[регистр][данные]` без последнего байта.

## 5. Общие регистры

| Адрес | Имя | Тип | Доступ | Описание |
|---|---|---|---|---|
| `0x00` | `WHO_AM_I` | u8 | RO | всегда `0x4D` |
| `0x01` | `PROTOCOL_VERSION` | u8 | RO | `1` |
| `0x02` | `FIRMWARE_VERSION` | u16 | RO | `(major << 8) \| minor`: `0x02` = minor, `0x03` = major |
| `0x04` | `STATUS` | u8 | RO | биты состояния, раздел 5.1 |
| `0x05` | `LAST_ERROR` | u8 | RO | код последней отклонённой записи, раздел 5.2 |
| `0x06` | `STOP_REASON` | u8 | RO | почему модуль остановил моторы, раздел 5.3 |
| `0x07` | `MOTOR_COUNT` | u8 | RO | `4` |
| `0x08` | `COMMAND` | u8 | WO | команда, раздел 5.4; читается как 0 |
| `0x09` | `STOP_MOTOR` | u8 | RO | номер мотора 0..3 для `STOP_REASON` 3, 4; иначе `0xFF` |
| `0x0A` | `WATCHDOG_MS` | u16 | RW | таймаут watchdog связи, 50..10000 мс, по умолчанию 500 |
| `0x0C` | `UPTIME_MS` | u32 | RO | время с запуска модуля, мс |
| `0x10` | `FRAMES_OK` | u16 | RO | принятые записи (по модулю 65536) |
| `0x12` | `FRAMES_REJECTED` | u16 | RO | отклонённые записи (по модулю 65536) |
| `0x14` | `RESET_FLAGS` | u8 | RO | причина последнего сброса MCU, раздел 5.5 |
| `0x0E–0x0F`, `0x15–0x1F` | — | — | — | резерв, читается как 0, запись — ошибка |

Чтение всех общих регистров одной транзакцией: адрес `0x00`, 21 байт.

### 5.1. STATUS

| Бит | Имя | Значение |
|---|---|---|
| 0 | `ESTOP` | была команда `ESTOP` |
| 1 | `WATCHDOG` | сработал watchdog связи |
| 2 | `MOTOR_FAULT` | у какого-то мотора защёлкнута ошибка защиты (`FLAGS` бит 2 или 3) |
| 3 | `CRC_ERROR` | была запись с неверным CRC |
| 4 | `FRAME_ERROR` | была запись с ошибкой длины, адреса или в регистр только для чтения |
| 5 | `VALUE_ERROR` | была запись со значением вне диапазона |
| 6 | `STATE_ERROR` | была попытка запустить мотор при блокировке |
| 7 | `RX_OVERFLOW` | запись потеряна: очередь (8 записей) была полна |

Все биты — **защёлки**: остаются установленными до команды
`CLEAR_ERRORS`. Биты 0–2 — **блокирующие**: пока любой из них установлен,
запись `MODE` = `PWM` или `SPEED` отклоняется с ошибкой `STATE`. Бит 2
зависит от моторов: он сбрасывается вместе с их защёлками той же командой.

### 5.2. LAST_ERROR

| Код | Имя | Причина |
|---|---|---|
| 0 | `NONE` | ошибок нет (после `CLEAR_ERRORS` или с запуска) |
| 1 | `CRC_MISMATCH` | CRC-8 не совпал |
| 2 | `LENGTH` | запись из двух байтов (нет данных или нет CRC) или данных не хватает до конца регистра |
| 3 | `BAD_ADDRESS` | на этом адресе не начинается регистр: резерв, середина регистра или за `0x9F` |
| 4 | `READ_ONLY` | запись в регистр только для чтения |
| 5 | `VALUE` | значение вне допустимого диапазона |
| 6 | `STATE` | `MODE` = `PWM` / `SPEED` при блокировке (`STATUS` биты 0–2) или при ошибке этого мотора |
| 7 | `RX_OVERFLOW` | запись потеряна: очередь переполнилась |

Отклонённая запись **ничего не меняет**: ни один из её регистров не
применяется.

### 5.3. STOP_REASON

| Код | Причина | `STOP_MOTOR` |
|---|---|---|
| 0 | нет (с запуска или после `CLEAR_ERRORS`) | `0xFF` |
| 1 | команда `ESTOP` | `0xFF` |
| 2 | watchdog связи | `0xFF` |
| 3 | заклинивание (stall) мотора | 0..3 |
| 4 | мотор вращается не в ту сторону | 0..3 |

Хранится последняя причина. Остановки по командам master (`MODE` =
`COAST`/`BRAKE`, `COAST_ALL`) сюда не пишутся.

### 5.4. COMMAND

| Код | Имя | Действие |
|---|---|---|
| `0x01` | `ESTOP` | все моторы — `BRAKE`, защёлка `STATUS.ESTOP`, `STOP_REASON` = 1 |
| `0x02` | `CLEAR_ERRORS` | сбрасывает все биты `STATUS`, ошибки моторов (`FLAGS` биты 2–4), `LAST_ERROR`, `STOP_REASON`, `STOP_MOTOR`. Режимы моторов **не меняет** |
| `0x03` | `RESET_ENCODERS` | обнуляет `ENCODER` всех моторов |
| `0x04` | `COAST_ALL` | все моторы — `COAST`, без защёлок |

Другие коды — ошибка `VALUE`.

### 5.5. RESET_FLAGS

| Бит | Причина |
|---|---|
| 0 | включение питания (POR) |
| 1 | кнопка RESET / вывод NRST |
| 2 | программный сброс (в том числе переход из HID Bootloader) |
| 3 | сработал IWDG: прошивка зависла |

Флаги снимаются из `RCC->CSR` при запуске. Если загрузчик сам их
очищает, часть причин может не отображаться. Надёжный признак
перезапуска модуля — `UPTIME_MS` уменьшился. После перезапуска все
моторы в `COAST`, а уставки и настройки — по умолчанию.

## 6. Регистры мотора

Смещения от начала блока мотора (`0x20`, `0x40`, `0x60`, `0x80`).

| Смещение | Имя | Тип | Доступ | Единицы, диапазон | По умолчанию |
|---|---|---|---|---|---|
| `0x00` | `MODE` | u8 | RW | раздел 6.1 | 0 (`COAST`) |
| `0x01` | `CONFIG` | u8 | RW | раздел 6.2 | 0 |
| `0x02` | `PWM_TARGET` | i16 | RW | промилле, −1000..1000 | 0 |
| `0x04` | `SPEED_TARGET` | i16 | RW | 0.1 об/мин, −4000..4000 (±400 об/мин) | 0 |
| `0x06` | `MAX_OUTPUT` | u16 | RW | промилле, 0..1000 | 900 |
| `0x08` | `KP` | u16 | RW | 0.01 промилле / (об/мин) | 150 (1.5) |
| `0x0A` | `KI` | u16 | RW | 0.01 промилле / (об/мин·с) | 800 (8.0) |
| `0x0C` | `KD` | u16 | RW | 0.01 промилле / (об/мин/с) | 0 |
| `0x0E–0x0F` | — | | | резерв | |
| `0x10` | `FLAGS` | u8 | RO | раздел 6.3 | |
| `0x11` | — | | | резерв | |
| `0x12` | `SPEED` | i16 | RO | 0.1 об/мин, измеренная скорость выходного вала | |
| `0x14` | `OUTPUT` | i16 | RO | промилле, текущий выход на драйвер со знаком | |
| `0x16–0x17` | — | | | резерв | |
| `0x18` | `ENCODER` | i32 | RW | отсчёты x4, запись задаёт счёт | 0 |
| `0x1C–0x1F` | — | | | резерв | |

Блок устроен так, чтобы можно было:

- записать `MODE`..`KD` (`0x00..0x0D`, 14 байтов) одной транзакцией;
- прочитать телеметрию `FLAGS`..`ENCODER` (`0x10..0x1B`, 12 байтов) одной
  транзакцией.

### 6.1. MODE

| Код | Режим | Что делает |
|---|---|---|
| 0 | `COAST` | выбег: оба входа `LOW`. Сразу |
| 1 | `BRAKE` | тормоз: оба входа `HIGH`. Сразу |
| 2 | `PWM` | выход = `PWM_TARGET` без обратной связи, с плавным разгоном 150 %/с |
| 3 | `SPEED` | PID держит `SPEED` = `SPEED_TARGET`. При `SPEED_TARGET` = 0 — выход 0 (выбег) |

Во всех режимах выход ограничен `±MAX_OUTPUT`, а смена направления идёт
через 0 и паузу 300 мс. Переход в `PWM` / `SPEED` отклоняется (ошибка
`STATE`), если установлен любой из битов `STATUS` 0–2 или у этого мотора
защёлкнута ошибка.

В режиме `SPEED` регулятор толкает мотор только в сторону уставки: при
положительной уставке выход 0..`MAX_OUTPUT`, при отрицательной
−`MAX_OUTPUT`..0. Тормозить регулятор не умеет — для удержания вала на
месте используйте `BRAKE`.

### 6.2. CONFIG

| Бит | Имя | Действие |
|---|---|---|
| 0 | `INVERT_MOTOR` | меняет направление вращения: положительный выход крутит «назад» |
| 1 | `INVERT_ENCODER` | меняет знак счёта энкодера и скорости |
| 2–7 | — | должны быть 0, иначе ошибка `VALUE` |

Настройте так, чтобы при положительном `PWM_TARGET` мотор крутился в
нужную сторону, а `SPEED` был положительным. Если знак `SPEED` не совпадает
со знаком выхода, режим `SPEED` даст ошибку «не то направление».

### 6.3. FLAGS

| Бит | Имя | Тип | Значение |
|---|---|---|---|
| 0 | `REVERSING` | текущий | выход удерживается в 0 перед сменой направления |
| 1 | `SATURATED` | текущий | выход упёрся в `MAX_OUTPUT` |
| 2 | `FAULT_STALL` | защёлка | заклинивание: в `SPEED` выход ≥ 50 % (или ≥ `MAX_OUTPUT`, если он меньше), а вал медленнее 3 об/мин дольше 1 с |
| 3 | `FAULT_DIRECTION` | защёлка | в `SPEED` вал вращается против выхода быстрее 20 об/мин и не замедляется за 300 мс |
| 4 | `ENCODER_GLITCH` | защёлка | программный энкодер (моторы 3, 4) пропустил переход: помехи или слишком высокая частота |
| 5–7 | — | | 0 |

При ошибке защиты (биты 2, 3) мотор переходит в `BRAKE`, `STOP_REASON` и
`STOP_MOTOR` указывают причину, `STATUS.MOTOR_FAULT` = 1. Защёлки
снимает `CLEAR_ERRORS`.

### 6.4. ENCODER и SPEED

- `ENCODER` — накопленный счёт, 1320 отсчётов на оборот выходного вала
  (редуктор 1:30). Положительное направление — то же, что у `SPEED`.
- Запись `ENCODER` задаёт текущее значение (например, 0). Скорость при
  этом не скачет.
- `SPEED` считается по приращению счёта за 10 мс со сглаживанием
  (`SPEED_FILTER_ALPHA` = 0.3). Шаг измерения — около 4.5 об/мин за один
  период, сглаживание делает показания плавнее, но с задержкой ~30 мс.

## 7. Watchdog связи

- Работает, только если хотя бы один мотор в `PWM` или `SPEED`.
- Любая транзакция по адресу модуля (чтение или запись, даже
  отклонённая) — это «обращение».
- Если обращений не было дольше `WATCHDOG_MS` (по умолчанию 500 мс): все
  моторы — `BRAKE`, `STATUS.WATCHDOG` = 1, `STOP_REASON` = 2.
- Чтобы снова запустить моторы: `CLEAR_ERRORS`, затем `MODE`. Модуль не
  поедет сам после восстановления связи.
- Master, у которого моторы в движении, должен обращаться к модулю чаще
  `WATCHDOG_MS`. Удобно опрашивать телеметрию каждые 50–100 мс.

Отдельно работает аппаратный IWDG MCU (250 мс): если прошивка зависнет,
модуль перезапустится, и моторы окажутся в `COAST`.

## 8. Примеры транзакций

Адрес модуля `0x20`, байт адреса для CRC — `0x40`. Байты в шестнадцатеричном
виде, `S`/`P` — старт/стоп, `Sr` — повторный старт.

### 8.1. Проверить модуль

```text
S 40 00 Sr 41 [4D] P                 WHO_AM_I = 0x4D
```

### 8.2. Мотор 1: держать 100.0 об/мин

```text
SPEED_TARGET = 1000 (0x03E8):  S 40  24 E8 03 91  P    CRC(40 24 E8 03) = 91
MODE = SPEED (3):              S 40  20 03 21     P    CRC(40 20 03)    = 21
```

То же одной транзакцией (`MODE`, `CONFIG`, `PWM_TARGET`, `SPEED_TARGET`):

```text
S 40  20 03 00 00 00 DC 05 5B  P     MODE=3, CONFIG=0, PWM=0, SPEED=1500 (150.0 об/мин)
```

### 8.3. Мотор 2: назад 30 % без обратной связи

```text
PWM_TARGET = -300 (0xFED4):    S 40  42 D4 FE D1  P
MODE = PWM (2):                S 40  40 02 D3     P    регистр 0x40 = MODE мотора 2
```

### 8.4. Телеметрия мотора 1

```text
S 40 30 Sr 41 [FLAGS] [--] [SPEED lo hi] [OUTPUT lo hi] [-- --] [ENCODER b0 b1 b2 b3] P
```

12 байтов с `0x30` (= `0x20 + 0x10`).

### 8.5. Команды

```text
ESTOP:          S 40  08 01 29  P
CLEAR_ERRORS:   S 40  08 02 20  P
WATCHDOG_MS = 1000:  S 40  0A E8 03 FE  P
```

### 8.6. Linux (i2c-tools)

```sh
i2cget -y 1 0x20 0x00 b          # WHO_AM_I
i2cset -y 1 0x20 0x08 0x02 bp    # CLEAR_ERRORS с PEC
i2cset -y 1 0x20 0x24 0x03e8 wp  # SPEED_TARGET мотора 1 = 100.0 об/мин
i2cset -y 1 0x20 0x20 0x03 bp    # MODE мотора 1 = SPEED
```

На Raspberry Pi аппаратный I2C плохо переносит растяжку SCL; если чтения
сбоят, см. [troubleshooting.md](troubleshooting.md).

## 9. Типовая последовательность master

1. Прочитать `WHO_AM_I` и `PROTOCOL_VERSION`; при несовпадении — не
   работать с модулем.
2. При необходимости записать `WATCHDOG_MS`, `CONFIG`, `MAX_OUTPUT`,
   коэффициенты PID.
3. `CLEAR_ERRORS` — модуль мог остаться в защёлке с прошлого сеанса.
4. Записать уставки и `MODE`.
5. Каждые 50–100 мс читать телеметрию моторов и `STATUS`:
   - бит 0–2 установлен → моторы остановлены модулем, выяснить причину
     по `STOP_REASON` / `STOP_MOTOR`, устранить, `CLEAR_ERRORS`, заново `MODE`;
   - биты 3–7 → какая-то запись не прошла, `LAST_ERROR` объяснит.
6. Следить за `UPTIME_MS`: если он уменьшился, модуль перезапустился —
   повторить шаги 2–4.
7. Завершение: `COAST_ALL` или `MODE` = `BRAKE`.
