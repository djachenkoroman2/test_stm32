# motor_i2c_module

Модуль управления четырьмя DC-моторами с энкодерами на Blue Pill
(STM32F103C8T6). Модуль — I2C slave: master задаёт режим и уставку каждого
мотора, а модуль сам держит скорость по энкодеру (PID) и следит за
безопасностью.

Код: [`src/motor_i2c_module/`](../../src/motor_i2c_module/). Окружение:
`[env:motor_i2c_module]` в `platformio.ini`.

## Возможности

- 4 мотора JGB37-520 через два ZK-5AD, ШИМ 20 кГц.
- 4 квадратурных энкодера x4: моторы 1, 2 — аппаратно (TIM1, TIM4),
  моторы 3, 4 — по прерываниям.
- Режимы каждого мотора: выбег, тормоз, ШИМ без обратной связи, скорость
  по PID (об/мин выходного вала).
- Безопасность:
  - входы ZK-5AD в `LOW` с первых строк `setup()`;
  - смена направления только через 0 и паузу 300 мс;
  - предел выхода (по умолчанию 90 %) и плавный разгон в режиме ШИМ;
  - watchdog связи: тормоз всех моторов, если master молчит дольше 500 мс;
  - аварийная остановка одной командой;
  - защиты от заклинивания и вращения не в ту сторону;
  - после любой остановки модулем моторы не запустятся без `CLEAR_ERRORS`;
  - аппаратный IWDG на случай зависания прошивки.
- I2C: адрес 0x20, 100/400 кГц, карта регистров, CRC-8 (SMBus PEC) на
  каждой записи.
- Отладочный вывод в Serial по USB, не влияющий на контур.
- Прошивка по USB через HID Bootloader.

## Быстрый старт

1. Соберите и подключите всё по [wiring.md](wiring.md), пройдите чек-лист.
2. Прошейте модуль:
   ```sh
   pio run -e motor_i2c_module -t upload
   pio device monitor -e motor_i2c_module
   ```
3. Прошейте master (ESP32) скетчем из
   [examples/esp32_master](examples/esp32_master/esp32_master.ino) и
   откройте его Serial Monitor (115200).
4. Мотор 1 на 100 об/мин:
   ```text
   clear
   speed 1 100
   mode 1 speed
   m 1
   ```
5. Полная проверка — [testing.md](testing.md).

## Сводка протокола

| Адрес | Регистр | Назначение |
|---|---|---|
| `0x00` | `WHO_AM_I` | `0x4D` |
| `0x04` | `STATUS` | ошибки и блокировки |
| `0x08` | `COMMAND` | `1` ESTOP, `2` CLEAR_ERRORS, `3` RESET_ENCODERS, `4` COAST_ALL |
| `0x0A` | `WATCHDOG_MS` | таймаут связи |
| `0x20 + 0x20·n + 0x00` | `MODE` | `0` COAST, `1` BRAKE, `2` PWM, `3` SPEED |
| `… + 0x02` | `PWM_TARGET` | промилле, −1000..1000 |
| `… + 0x04` | `SPEED_TARGET` | 0.1 об/мин, −4000..4000 |
| `… + 0x08..0x0D` | `KP`, `KI`, `KD` | сотые |
| `… + 0x12` | `SPEED` | измеренная скорость, 0.1 об/мин |
| `… + 0x18` | `ENCODER` | счёт, 1320 на оборот |

Запись: `[регистр][данные little-endian][CRC-8]`. Чтение: `[регистр]`,
повторный старт, чтение. Подробно — [i2c-protocol.md](i2c-protocol.md).

## Характеристики прошивки

| Параметр | Значение |
|---|---|
| Flash | 48 104 байта из 63 488 доступных (64 КБ минус 2 КБ HID Bootloader), 76 % |
| RAM | 6 104 байта из 20 480, 30 % |
| Период контура | 10 мс |
| Частота ШИМ | 20 кГц, 3600 шагов |
| Нагрузка прерываниями энкодеров 3, 4 | до ~15 000 в секунду на полной скорости, 2–3 % процессора |

## Структура кода

| Файл | Назначение |
|---|---|
| `config.h` | пины, параметры мотора, PID, защиты, адрес I2C — все константы |
| `register_map.h` | адреса регистров, коды ошибок, биты `STATUS` |
| `zk5ad_driver.*` | канал ZK-5AD на двух каналах таймера |
| `quadrature_encoder.*` | энкодер: режим энкодера таймера или EXTI |
| `speed_meter.h` | скорость по приращению счёта |
| `pid_controller.h` | PID с защитой от накопления интеграла |
| `motor_channel.*` | мотор: режимы, выходной каскад, защиты |
| `module_state.*` | защёлки, аварийная остановка, watchdog связи |
| `i2c_link.*` | I2C slave: очередь записей и снимок для чтения (прерывание) |
| `registers.*` | разбор записей, проверка, CRC, снимок регистров |
| `debug_log.*` | неблокирующий вывод в Serial |
| `main.cpp` | `setup()` / `loop()`, светодиод, строка состояния |

## Допущения и что проверить на железе

Прошивка собрана, но на оборудовании не проверялась. Проверить нужно:

- что ZK-5AD принимает 3.3 В на входах и работает на 20 кГц;
- что параметры моторов совпадают с `config.h` (12 В, 1:30, 11 импульсов);
- что коэффициенты PID по умолчанию подходят для ваших моторов и нагрузки
  (они взяты со стенда с одним JGB37-520 на ESP32);
- направление счёта аппаратных энкодеров (TIM1, TIM4) и программных
  (EXTI) совпадает — должно, но проверяется шагом 4 testing.md;
- работу I2C slave при 400 кГц и длительной нагрузке (шаг 9 testing.md);
- флаги `RESET_FLAGS` с HID Bootloader (загрузчик может их менять).

Настройки (`CONFIG`, PID, `MAX_OUTPUT`, `WATCHDOG_MS`) хранятся только в
RAM и после перезапуска возвращаются к значениям по умолчанию.
